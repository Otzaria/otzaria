# ניסוי השוואת מסלולי WebView ב־Windows

תשתית לאיסוף נתונים עבור #4110. הכלי אינו משנה את ברירת המחדל של אוצריא,
אינו קובע ש־HWND עדיף, ואינו משלים לבדו את בדיקות התאימות של ה־issue.

## הרצה

נדרשים Windows, PowerShell 7 ו־build זהה של אוצריא במצב Release/Profile.
השתמש בפרופיל בדיקה: פתיחת האפליקציה והפעלת התוספים עשויות לשמור מצב כרגיל.
הכלי אינו מגבה, מוחק או משחזר נתוני משתמש, ואינו מסיים תהליכים בכוח.
סגור מופעים קודמים של האפליקציה לפני ההרצה.

```powershell
pwsh -File tool/perf_probe/run_webview_hosting_probe.ps1 `
  -Executable 'D:\Otzaria-test\otzaria.exe' `
  -OutDirectory 'D:\measurements\webview-idle-01' `
  -Scenario 'חמישה טאבי תוסף זהים, ארבעה מוסתרים, ללא הקלדה או גלילה' `
  -DisplaySetup '1920x1080, scaling 100%, viewport קבוע' `
  -Pairs 2 -Seconds 30
```

כל זוג כולל הפעלה רגילה והפעלה עם `FLUTTER_INAPPWEBVIEW_WINDOWS_FORCE_HWND=1`.
סדר ההפעלות מתחלף AB/BA. הדגל משתנה רק בסביבת תהליך הילד.
בכל הפעלה מכינים ידנית **אותו** עומס ולוחצים Enter להתחלת האיסוף.
לאחר האיסוף סוגרים את האפליקציה כרגיל ומאשרים שהסתיימה.
תיקיית פלט קיימת אינה נדרסת. כשל משאיר את התוצאות החלקיות לבדיקה.

## נתונים ומגבלות

- `metadata.json`: SHA-256 של ה־EXE, תיאור התרחיש/תצוגה, מערכת, מעבדים
  לוגיים ופרטי GPU/דרייבר ככל שהם זמינים. יש לצרף בנפרד גרסת WebView2,
  commit האפליקציה/הפורק, גרסאות התוספים ומצב חיסכון בחשמל.
- קובץ JSONL לכל ניסיון: PID מדויק של המופע שהכלי פתח, תהליכי־הבן שנצפו,
  זמן CPU מצטבר, private commit ו־working set בבייטים. Working set אינו
  private commit וסכומו עשוי לספור דפים משותפים כמה פעמים.
- כל קשר הורות נבדק גם לפי `CreationDate`: תהליך שנוצר לפני ההורה הנוכחי
  אינו שייך אליו רק מפני ש־Windows השתמש שוב ב־PID. זהות שלא ניתן לאמת
  נספרת כחסרה ואינה מרחיבה את העץ; שורש חסר או מוחלף מפסיק את הניסיון.
  זמן היצירה נבדק גם לפני ואחרי קריאת המונים. ההשוואה ל־CIM מאפשרת רק
  הפרש קטן ממיקרו־שנייה, בהתאם לדיוק התאריך שלו, ולא חלון זמן שרירותי.
- CPU מחושב בין דגימות עם אותה קבוצת זהויות תהליך (PID + זמן יצירה).
  100% משמעו ליבה אחת מלאה, לא כלל המחשב. חילופי תהליכים, דגימה חסרה או
  counter שאינו תקין נותנים `null`, לא אפס. תהליכים שנולדו ונסגרו בין דגימות
  אינם נצפים: זהו אומדן מבוסס דגימות, לא מדידת CPU מלאה של כל ההרצה.
- ניסיון תקין מסתיים ברשומת `end` עם `complete=true`, רק לאחר בדיקת חיות
  נוספת בסוף האיסוף. סגירה בזמן ההמתנה האחרונה אינה נחשבת להשלמה.
  אין להשוות ניסיון חסר או להסיק שהשלמת הזמן מבטיחה שכל מוניו זמינים.
- `default` הוא **מצב מבוקש** בלבד: אם הפורק נפל ל־HWND, ההרצה אינה
  השוואת composition מול HWND. יש לאמת את המסלול בפועל באמצעות
  הדיאגנוסטיקה/בדיקות ההטמעה לפני הסקת מסקנה.
- הכלי לא אוסף זיכרון GPU, זמן אתחול, זמן חידוש או p95 של פריימים. יש
  לצרף אותם מכלי המערכת ומלוג הדיאגנוסטיקה של האפליקציה. אין לפרש חסר כאפס.

בצע ניסיונות נפרדים עבור idle, גלילה, resize, טאבים מוסתרים וחידוש.
פעולות ידניות אינן מתוזמנות אוטומטית; יש לתעד אותן ולחזור עליהן בעקביות.
השלם על שתי תצורות GPU לפחות ובדוק גם RTL, פוקוס, חפיפת תפריטי Flutter,
שינוי DPI וריבוי חלונות. רק אז ניתן להחליט על שינוי ברירת מחדל.

לבדיקת lifecycle, השווה את אותו רצף פתיחה, הסתרה, חידוש וסגירה חוזרת
באותו מסלול hosting ובאותה תצורת תוספים. בצע דגימת סרק לפני הרצף ואחריו
והצלב עם דיאגנוסטיקת האפליקציה למספר hosts ולהצלחת suspend/resume.
מספר תהליכי־בן אינו מספר hosts: כמה WebViews עשויים לשתף תהליך.

חוזי המקור: [זהות והורות ב־Win32_Process](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process#properties),
[דיוק תאריכי DMTF](https://learn.microsoft.com/en-us/dotnet/api/system.management.managementdatetimeconverter.todmtfdatetime).

## בדיקות הכלי

```powershell
pwsh -File tool/perf_probe/test_webview_hosting_probe.ps1
```

הבדיקות אינן פותחות את אוצריא: הן בודקות חישוב CPU, זהות תהליכים, חסרים,
מחזורים בעץ, שימוש חוזר ב־PID בזמן איסוף, שחרור handles, יציאה בהמתנה
האחרונה והפרדת משתנה הסביבה. ה־workflow מריץ אותן ב־Windows וב־Linux;
איסוף משאבים אמיתי עדיין דורש הרצה ייעודית ב־Windows.
