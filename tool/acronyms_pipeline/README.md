# צינור האימות של מילון ראשי התיבות

כלים לאיסוף הצעות ולאימות אנושי לפני הרחבת `assets/Acronyms.json`. **רק רשומה בסטטוס `approved`, עם בודק אנושי מזוהה, תאריך ואסמכתה, נכנסת למילון.** בדיקת AI אינה מחליפה אימות ידני של כל זוג. הכלים והסינון אינם מאמתים את נכונות הפירוש.

מילון הייצור כולל את ערכי "ספר ראשי תיבות" של שטרן (ספר מודפס מ־1926, נחלת הכלל) שהמרתם נבדקה בידי סוכן. שאר ההצעות ב־`data/decisions.csv` עדיין לא נכנסו. `agent_approved` מתעד בדיקת סוכן בלבד, לא אישור אנושי. רשימת ההצעות כוללת גם טעויות שדורשות בירור, כגון שיוך „דיני חול המועד” לדכ״א במקום לדח״ה אצל שטרן, שסומן `needs_review`.

## מקורות

פרטי המקורות והרישיונות נמצאים ב־`data/sources.json`. ג'סטרו, ספר ראשי תיבות של שטרן והפניות מפורשות בספרייה הם אסמכתאות לבדיקה; גם אז האדם צריך לוודא את המפתח והפירוש במקור. רמזי דיקטה ובדיקות סוכן דורשים אסמכתה עצמאית שהאדם מצא. אוצר הספרים היהודי השיתופי חסום, ולא נעשה בו שימוש.

## בדיקת ההצעות שכבר נאספו

מהתיקייה הראשית של המאגר:

```bash
python3 tool/acronyms_pipeline/make_review_page.py --ledger --out /tmp/acronym-review.html
```

הדף המקומי מציג עד 100 הצעות ללא אישור מוקדם. פותחים אותו בדפדפן, מקלידים את שם הבודק, בודקים כל זוג מול האסמכתה, מאשרים או דוחים ומייצאים CSV. אין לאשר את הרשימה כולה על סמך מדגם. לאחר ייבוא ההחלטות מפעילים שוב את אותה הפקודה, ללא `--offset`: אישורים ודחיות מיובאים יוצאים מהתור, והאצווה הבאה מתחילה בהצעה הראשונה שנותרה. רשומות `needs_review` נשארות בתור ויופיעו שוב; יש להכריע בהן מול מקור או להשאירן לבדיקה מאוחרת. `--limit` משנה את גודל האצווה. `--offset` מיועד רק לחלוקת עבודה מראש מתוך עותק קבוע של הרשימה, ולא להגדלה אחרי כל ייבוא. אפשר להעביר נתיב אחרי `--ledger` ורצוי לציין `--baseline` כאשר מכינים קובץ על בסיס אחר.

ההתקדמות נשמרת בנפרד לכל תוכן אצווה בדפדפן. יש לייצא ולייבא כל אצווה לפני מעבר לבאה. בעריכת פירוש, האישרור מתייחס לפירוש המתוקן בלבד; ההצעה המקורית נשארת ברשימת ההצעות עד הכרעה נפרדת.

```bash
git show origin/dev:assets/Acronyms.json > /tmp/acronym-baseline.json
python3 tool/acronyms_pipeline/merge.py --baseline /tmp/acronym-baseline.json --import /path/to/export.csv --out assets/Acronyms.json
python3 tool/acronyms_pipeline/merge.py --baseline /tmp/acronym-baseline.json --check
```

`merge.py` מאמת את הסטטוס, המקור, הבודק, התאריך, האסמכתה והסינון לפני כתיבה. `approved` (בודק אנושי מזוהה) נכנס תמיד. `agent_approved` נכנס רק ממקור שמסומן ב־`data/sources.json` בדגל `merge_agent_checked`: ספר שנכתב בידי אדם והסוכן בדק את המרתו. כרגע הדגל מסומן רק על `stern-ref`. `pending`, `needs_review` ו־`rejected` אינם נכנסים. `--human-only` בונה בלי שורות `agent_approved` בכלל. רשומות קיימות נשמרות בסדר המקורי; פירוש חדש מצורף לרשימת הפירושים ומפתח חדש מוכנס במקום האלפביתי שלו.

## איסוף הצעות נוספות

`collect_jastrow.py` ו־`collect_corpus.py` אוספים מועמדים. `build_candidates.py` מסנן ומדרג, ויוצר `candidates.jsonl`, `review.csv` ודוח. להכנת דף מהמועמדים החדשים:

```bash
python3 tool/acronyms_pipeline/make_review_page.py --candidates /path/to/candidates.jsonl --out /tmp/acronym-review.html
```

`filters.py` מסנן ריקים, שיבושי מבנה, HTML, שמות אותיות בלבד, מספרי גימטריה, כפילויות וצורות עם אות שימוש. התאמה חלשה בין האותיות למילים מסומנת לבדיקה. מעבר בסינון אינו אישור תוכן. מפתחות עם כמה ראשי תיבות ברצף, למשל דע״ד בל״ד, אינם יכולים להיכנס תחת ראשי התיבות הראשונים בלבד.

## הצעות לניקוי הקובץ הקיים

`clean_baseline.py` יוצר `data/baseline_removals.csv`: כל פירוש קיים שנפסל בסינון, עם הסיבה. `merge.py` מוחק מהקובץ הקיים רק פירושים שהסיבה שלהם `same_as_key`, `expansion_is_acronym` או `structure_chars`, כלומר הפירוש הוא המפתח עצמו (רמ״בם = רמבם) או ראשי תיבות אחרים, ואינו מפענח דבר. שורות `gematria_number` נשארות ברשימה כהצעות בלבד ואינן נמחקות, כי חלקן שימושי (ט״ו = חמישה עשר). מפתח שנשאר בלי פירושים יוצא מהקובץ. ה־baseline של `merge.py` הוא הקובץ כפי שהיה לפני השינוי הזה (`git show 35e23e7f5:assets/Acronyms.json`); בלעדיו אי אפשר לשחזר את המחיקות.
