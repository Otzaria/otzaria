# מסדי ספרים אישיים

המדריך מיועד למשתמשים ולמי שבונה מסד ספרים משלו. מסד ספרים אישי הוא קובץ SQLite
במבנה של ספריית אוצריא (כמו `seforim.db`), שמצורף לספרייה ומוצג לצד הספרים הרשמיים
והאישיים. אפשר לצרף מסד אחד או כמה.

## צירוף מסד

הגדרות ← לשונית "ספרייה" ← הכרטיס **"מסדי ספרים אישיים"**:

- **"הוסף קובץ מסד"** — בחירת קובץ `.db` בודד.
- **"הוסף תיקיית מסדים"** — כל קובץ `*.db` בתיקייה מצורף. התיקייה נסרקת אחרי עליית
  התוכנה ובסריקה ידנית חוזרת.

### מצבי צירוף

| מצב | ברירת מחדל ב- | התנהגות |
|---|---|---|
| קישור במקום | מחשב | הקובץ נקרא במקומו ולעולם אינו משתנה. מסד שיש לו קובץ `-wal` או journal "חם" נדחה — יש לסגור אותו כראוי בכלי שיצר אותו. |
| העתקה | נייד | הקובץ מועתק לתיקיית נתוני התוכנה, לתיקייה "מסדים אישיים". ה-journal מנורמל על ההעתק. |

### פעולות לכל מסד

- **מיקום בעץ**: "בנפרד" — תחת השורש "ספרים אישיים/<שם התצוגה>"; או "ממוזג" — הספרים
  משתלבים בקטגוריות הספרייה לפי כותרת הקטגוריה. ספרי מסד מצורף תמיד ממוינים אחרי
  הספרים הרשמיים והאישיים. מסד שמצהיר על `library_folder` מוצג תמיד בתיקייה הזו ברמה
  העליונה של העץ, ובחירת המיקום אינה חלה עליו.
- **הסתרה**, **סדר עדיפות** בין המסדים.
- **"שחרר קובץ"** — משחרר את נעילת הקובץ ב-Windows כדי שאפשר יהיה להחליף אותו.
- **הסרה** — קובץ מקושר לעולם אינו נמחק; העתק מנוהל נמחק אחרי אישור.

### מסד לא זמין או איטי

- מסד שאינו נגיש (כונן נשלף, כונן רשת): הספרים שלו מוסתרים והסטטוס "לא זמין", אבל
  ההגדרות, אינדקס החיפוש, הסימניות וההערות נשמרים. כשהמסד חוזר — הכול חוזר.
- לכל מסד תקציב זמן משלו בבניית עץ הספרייה. מסד שלא עונה מסומן "לא זמין" והעץ ממשיך
  להיבנות בלעדיו.

## זהות המסד (slug)

- ה-slug נלקח מ-`schema_meta.library_id` אם קיים, אחרת משם הקובץ אחרי ניקוי.
- תווים מותרים: אותיות (כולל עברית), ספרות, `.` `_` `-`; עד 64 תווים.
- שני קבצים עם אותו slug — השני נדחה.
- **שמרו על `library_id` יציב בין גרסאות** — עליו נשענים סימניות, אינדקס החיפוש והערות.
- החלפת הקובץ בגרסה חדשה (אותו slug) ← רק ספרי המסד הזה מאונדקסים מחדש.

מפתחות `schema_meta` שנקראים: `library_id`, `library_name` (שם התצוגה), `db_version`,
`library_folder` (שם תיקייה ברמה העליונה של עץ הספרייה: ספרי המסד מוצגים בה במקום תחת
"ספרים אישיים". הגדרות המיזוג אינן משפיעות עליה, ומסדים שמצהירים על אותו שם חולקים אותה. היא אינה מתמזגת
לקטגוריה רשמית או אישית באותו שם. ערך עם `/` או `\`, ארוך מ-64 תווים או "ספרים אישיים" אינו
נחשב); וכן
`description`, `author` (אופציונליים, לידיעה בלבד).

## קטלוג הטבלאות

**אף טבלה אינה חובה.** טבלה חסרה ← רק היכולת התלויה בה ריקה. מסד מינימלי שימושי:
`book` + `line`.

| טבלה / זוג | תפקיד | הערות |
|---|---|---|
| `category` | עץ הקטגוריות | בלעדיה הספרים יושבים ישירות תחת שורש המסד |
| `book` | הספרים | עמודות אופציונליות: `heDesc`, `orderIndex`, `filePath` |
| `line` | טקסט הספר | שורה אחת לכל רשומה, `lineIndex` מתחיל מ-0 |
| `tocText` + `tocEntry` | תוכן עניינים | |
| `line_toc` | פירורי לחם (מיקום בתוכן העניינים) | |
| `author` + `book_author` | פרטי ספר: מחבר | |
| `topic` + `book_topic` | פרטי ספר: נושאים | |
| `pub_place` + `book_pub_place` | פרטי ספר: מקום הוצאה | |
| `pub_date` + `book_pub_date` | פרטי ספר: שנת הוצאה | |
| `generation` + `book_generation` | דור/תקופה | קיבוץ ומיון מפרשים |
| `connection_type` + `link` | קישורים ומפרשים בתוך אותו מסד | |
| `link_anchor` | עוגני מילים לקישורים | |
| `link_range` + `link_coverage` | טווחי קישור | **חייבות לבוא יחד** |
| `link_suppressed_side` | הסתרת צד של קישור | |
| `default_commentator` / `default_targum` | ברירות מחדל לצורת הדף | |
| `alt_toc_structure` + `alt_toc_entry` (+ `line_alt_toc`) | לשונית "כותרות" | |
| `line_dh` | דיבור המתחיל | עמודה `dhDisplay` |
| `line_ref` | אינדקס הפניות | איתור מקור עד השורה המדויקת |
| `book_acronym` | ראשי תיבות | לחיפוש ספרים ולאיתור |
| `book_version` + `version_line` | מהדורות | **חייבות לבוא יחד** |
| `book_version_link` | ספר במסד כגרסה של ספר אחר | ראו בהמשך |
| `schema_meta` | מטא-דאטה של המסד | ראו למעלה |
| `external_link` | קישורים בין מסדים | ראו בהמשך |
| `external_default_commentator` | מפרש מהמסד כברירת מחדל לספר במסד אחר | ראו בהמשך |

כל טבלה אחרת (כולל טבלאות שנראות כמו טבלאות תוספים) **מתעלמים ממנה ולעולם אינה
נקראת**. שם טבלה מוכר שהוא VIEW או טבלה וירטואלית — מתעלמים ממנו.

### `book.filePath`

עמודה אופציונלית (למשל לקובץ PDF). הנתיב חייב להיות **יחסי לתיקיית המסד**. נדחים:
נתיב מוחלט, אות כונן, UNC, `..`, רכיב שכולו נקודות/רווחים, `:`, תו NUL.

### אינדקסים מומלצים למסד גדול

```sql
CREATE INDEX idx_line_book_index ON line(bookId, lineIndex);  -- רצוי אינדקס מכסה
CREATE INDEX idx_link_source ON link(sourceBookId, sourceLineId);
CREATE INDEX idx_link_target ON link(targetBookId, targetLineId);
CREATE INDEX idx_toc_entry_book ON tocEntry(bookId);
CREATE INDEX idx_external_link_source ON external_link(sourceBookId, sourceLineIndex);
```

## קישורים בין מסדים — `external_link`

| עמודה | טיפוס | משמעות |
|---|---|---|
| `sourceBookId` | INTEGER | `book.id` במסד הזה |
| `sourceLineIndex` | INTEGER | שורת המקור (מ-0) |
| `targetSource` | TEXT | `'official'`, או `library_id` של מסד מצורף אחר, או NULL = כל מקור (קודם הרשמי, אחר כך המסדים המצורפים לפי עדיפות) |
| `targetTitle` | TEXT | כותרת ספר היעד |
| `targetRef` | TEXT | heRef של היעד — מועדף; מתורגם דרך `line_ref` של מסד היעד |
| `targetLineIndex` | INTEGER | גיבוי (מ-0) כשאין `targetRef` |
| `connectionType` | TEXT | NULL ← `REFERENCE` |

ל-`connectionType` **אותה משמעות כמו בטבלת `link` הרשמית**: איך היעד מוצג לקורא בספר
המקור. לכן, כדי שהפירוש שלכם יופיע בחלונית המפרשים של ספר רשמי, כתבו
`connectionType='SOURCE'` — מבחינת הפירוש שלכם, הספר הרשמי הוא המקור:

```sql
CREATE TABLE external_link (
  sourceBookId INTEGER NOT NULL,
  sourceLineIndex INTEGER NOT NULL,
  targetSource TEXT,
  targetTitle TEXT NOT NULL,
  targetRef TEXT,
  targetLineIndex INTEGER,
  connectionType TEXT
);

-- שורה 0 של "פירוש על ספר א" (book.id = 1 במסד שלכם) מפרשת את "ספר א" הרשמי.
-- כך הפירוש יופיע בחלונית המפרשים של "ספר א".
INSERT INTO external_link
  (sourceBookId, sourceLineIndex, targetSource, targetTitle, targetRef, targetLineIndex, connectionType)
VALUES
  (1, 0, 'official', 'ספר א', 'ספר א א, א', NULL, 'SOURCE');
```

- הקישורים ההפוכים (מהספר הרשמי אל הפירוש) מוגשים מאינדקס צד שהתוכנה בונה ב-`cache.db`;
  הוא נבנה מחדש כשהקובץ שלכם או גרסת הספרייה הרשמית משתנים.
- מגבלות: עד 5,000,000 שורות למסד (מעבר לזה הטבלה מדולגת, ובכרטיס המסד בהגדרות מוצג "הקישורים החיצוניים לא נטענו — יותר מדי שורות"); כותרת והפניה נחתכות ב-512 תווים.

## מפרש ברירת מחדל לספר במסד אחר — `external_default_commentator`

`default_commentator` קובע ברירות מחדל רק לספרים שבתוך אותו מסד. כדי שפירוש מהמסד
שלכם ייפתח כברירת מחדל גם בספר רשמי (או בספר של מסד מצורף אחר):

```sql
CREATE TABLE IF NOT EXISTS external_default_commentator (
    targetSource TEXT,               -- 'official' / library_id של מסד אחר / NULL = כל מקור
    targetTitle TEXT NOT NULL,       -- כותרת הספר שהמפרש יוצג בו
    commentatorBookId INTEGER NOT NULL,  -- book.id במסד הזה
    kind TEXT NOT NULL DEFAULT 'commentator',  -- 'commentator' | 'targum'
    position INTEGER NOT NULL,
    PRIMARY KEY (targetSource, targetTitle, commentatorBookId, kind)
);
```

- **תנאי:** השורה פועלת רק כשהספר המפרש מקושר בפועל לספר היעד דרך `external_link`
  ומופיע ברשימת המפרשים שלו. שורה בלי קישור כזה — מתעלמים ממנה בשקט.
- **סדר:** אחרי מפרשי ברירת המחדל של הספר עצמו. בין מסדים — לפי סדר המסדים בהגדרות,
  ובתוך מסד — לפי `position`. `targum` מתווסף אחרי התרגומים של הספר עצמו.
- `kind` אחר מ-`commentator`/`targum` מתעלמים ממנו. ספר שכבר מופיע בברירות המחדל אינו
  מתווסף שוב.

## קובצי קישורים של המשתמש על ספרי מסד מצורף

קובצי הקישורים שהמשתמש מייבא (`<ספר>.links.csv|json`, `קישורים.csv`/`links.csv`,
`<ספר>_links.json`) יכולים לכוון לספר במסד מצורף בכל אחד מהצדדים:

- בלי ציון מקור: ספר שאינו נמצא בספרייה האישית או הרשמית (לפי מה שסומן בשורה) נלקח
  מהמסד המצורף הגלוי הראשון שמכיל אותו, לפי סדר העדיפות. ב-`<ספר>_links.json`, שאין
  בו עמודת מסד, כותרת שקיימת גם באישית/רשמית וגם במסד מצורף נדחית כדו-משמעית; קובץ
  שמור שנעשה כזה (למשל כשמסד מצורף נוסף אחריו) מדולג ומדווח בלי לחסום קבצים אחרים.
  ייבוא חדש או החזרת קובץ לשימוש נעצרים גם כשמסד מצורף גלוי אינו זמין לבדיקה
  ולא ניתן לשלול בו כותרת כפולה למועמד אישי או רשמי.
- ציון מפורש: העמודות `מסד_מקור` / `sourceDb` ו-`מסד_יעד` / `targetDb`, בערך `<id>`,
  `מסד:<id>` או `db:<id>`. מסד שאינו מכיל את הספר ← שגיאה.
- הצד המצורף נשמר לפי ה-slug והכותרת, בלי מזהה קטגוריה (מזהי הקטגוריות פנימיים למסד).
  מסד שהוסר — הקישורים שלו פשוט אינם מוצגים.

## ציטוט בגוף הטקסט בקובץ `<ספר>_links.json`

בקובץ קישורים בפורמט של אוצריא, `"Conection Type": "linker"` נשמר כמפרש: הוא מופיע
בחלונית המפרשים של הספר השני, ולא כקישור בגוף הטקסט. לציטוט שמסומן בגוף הטקסט
ונפתח בלחיצה ישר בספר היעד, כמו קישורי הלינקר בספרייה הרשמית, משתמשים בסוג
`INLINE_LINKER` (או `"ציטוט בטקסט"`). הציטוט יוצא משורת מקור אחת ויכול
להפנות לטווח שורות ביעד (`line_index_2_end`). חובה לציין `start` ו-`end`
כמיקומים בשורת ה-HTML השמורה, כולל תגיות וישויות, ביחידות UTF-16 החל מאפס.
`start` הוא תחילת הציטוט ו-`end` הוא המיקום שאחרי סופו.

```json
[{"line_index_1": 12, "start": 40, "end": 52, "path_2": "ברכות.txt",
  "line_index_2": 87, "heRef_2": "ברכות ב.", "Conection Type": "INLINE_LINKER"}]
```

## גרסאות: ספר אישי כגרסה של ספר אחר

קובץ `גרסאות.csv` / `versions.csv` — כקובץ צד בתיקיית ספרים אישיים, או בייבוא ידני
בהגדרות. עמודות: `ראשי`, `גרסה`, [`שם`], [`הערות`], [`עדיפות`], [`מקור_ראשי`],
[`קטגוריית_ראשי`], [`מסד_גרסה`].

ספר ה`גרסה` נלקח מהספרייה האישית, ואם אינו שם — מהמסד המצורף הגלוי הראשון שמכיל אותו
(בייבוא מההגדרות). `מסד_גרסה` (`<id>` / `מסד:<id>` / `db:<id>`) מכריע במפורש. גרסה
ממסד מצורף מוסתרת מהעץ ומוצגת בגרסאות הראשי, כמו גרסה אישית.

`מקור_ראשי`:

| ערך | הספר הראשי הוא |
|---|---|
| ריק / `אישי` / `user` | ספר אישי (ההתנהגות הקודמת — קבצים ישנים לא משתנים) |
| `רשמי` / `official` | ספר מהספרייה הרשמית |
| `מסד:<id>` / `db:<id>` | ספר במסד מצורף |

- ספר ראשי שאינו אישי מצוין תמיד **לפי כותרת** (לא לפי מזהה מספרי), כדי לשרוד עדכוני
  ספרייה. `קטגוריית_ראשי` מבחינה בין ספרים בעלי כותרת זהה.
- ראשי שלא נמצא ← הספר האישי נשאר ספר רגיל ועצמאי.
- דיאלוג הגרסאות של הספר הראשי ובורר הגרסאות בקורא מציגים את הגרסאות האישיות; בחירה
  פותחת את הספר האישי בכרטיסייה סמוכה.

```csv
ראשי,גרסה,שם,הערות,עדיפות,מקור_ראשי,קטגוריית_ראשי
ספר א,ספר א - מהדורה שלי,מהדורה מתוקנת,,1,רשמי,
ספר ב,ספר ב - העתק,,,2,db:my-library,קטגוריה א
```

### גרסאות מוטמעות במסד — `book_version_link`

מסד יכול להצהיר בעצמו שספר שלו הוא גרסה של ספר אחר, כך שמי שמצרף אותו מקבל את
הגרסאות בלי לייבא `גרסאות.csv`. השם `book_version` תפוס (מהדורות ברמת השורה), ולכן
זו טבלה נפרדת:

| עמודה | טיפוס | משמעות |
|---|---|---|
| `versionBookId` | INTEGER | `book.id` של ספר הגרסה במסד הזה (חובה) |
| `primarySource` | TEXT | `'official'` (גם NULL/ריק), `'user'`, או `'db:<library_id>'` |
| `primaryTitle` | TEXT | כותרת הספר הראשי (חובה) |
| `primaryCategoryPath` | TEXT | נתיב קטגוריה לפירוק כותרת כפולה, למשל `'תורה'` |
| `versionTitle` | TEXT | שם הגרסה לתצוגה; ריק ← כותרת ספר הגרסה |
| `versionNotes` | TEXT | הערות |
| `priority` | REAL | סדר בין הגרסאות (גבוה קודם) |

```sql
CREATE TABLE book_version_link (
  versionBookId INTEGER NOT NULL,
  primarySource TEXT,
  primaryTitle TEXT NOT NULL,
  primaryCategoryPath TEXT,
  versionTitle TEXT,
  versionNotes TEXT,
  priority REAL
);
INSERT INTO book_version_link VALUES (1, 'official', 'בראשית', 'תורה', 'נוסח הכתר', NULL, 1);
```

- ספר גרסה שהראשי שלו נמצא מוסתר מהעץ ומופיע בגרסאות הראשי. ראשי שלא נמצא ← הספר נשאר
  בעץ כרגיל.
- קובץ `גרסאות.csv` של המשתמש על אותו ספר גובר על הטבלה.
- נקראות עד 100,000 שורות למסד.

### ספר זהה לספר רשמי במיזוג

במצב "ממוזג", ספר שכותרתו (בהשוואה שמתעלמת מסוג הגרשיים ומרווחים) זהה לספר רשמי באותה
קטגוריה, ומאותו סוג (טקסט/PDF), אינו מוצג פעמיים: הוא הופך לגרסה של הספר הרשמי, בשם
המסד. הצהרה ב-`book_version_link` או בקובץ גרסאות על אותו ספר גוברת. במצב "בנפרד" אין
זיהוי כזה. ספר רשמי שהוסתר מהספרייה אינו נחשב, והספר מהמסד מוצג בעץ במקומו (הסתרה
חדשה נכנסת לתוקף בטעינת הספרייה הבאה).

## מה נתמך בספרי מסד מצורף

עץ הספרייה, קריאה, תוכן עניינים, קישורים ומפרשים (מקובצים לפי דור), צורת הדף,
"כותרות", דיבור המתחיל, מהדורות, PDF (נתיב יחסי), אינדקס חיפוש מלא (ספרים מצורפים
נוספים בסוף סדר הקטלוג, כך שצירוף מסד אינו מאנדקס מחדש ספרים אחרים), איתור מקורות
(כותרת, ראשי תיבות, תוכן עניינים, שורה מדויקת דרך `line_ref`; מוצג כשהאפשרות "כלול
ספרים אישיים" פעילה), חיפוש ספרים בספרייה (מדורגים אחרי רשמיים ואישיים), הדפסה,
הערות אישיות, סימניות והיסטוריה, ו-API התוספים.

**רק לספרייה הרשמית:** "דווח על טעות" ו"שמור וזכור".

## אבטחה

- המסד נפתח לקריאה בלבד: `query_only`, `trusted_schema=OFF`, מצב defensive, ללא
  הרחבות, mmap כבוי. לעולם לא נכתב אליו.
- **שום דבר מהמסד אינו מותקן או מורץ** — לא תוספים, לא סקריפטים, לא גופנים.
- קישורים שמוטמעים בטקסט הספר יכולים רק לנווט.
- נתיבי קבצים מוגבלים לתיקיית המסד.
- **עדכונים דרך פרוקסי HTTP:** חסימת כתובות פרטיות (localhost, רשת פנימית) נשענת על פענוח ה-DNS במכשיר.
  מאחורי פרוקסי הפרוקסי הוא שמפענח, ולכן הבדיקה אינה נועלת את הכתובת שאליה מתחברים בפועל.
- **פורטים:** כתובת https עם פורט שאינו 443 מותרת (למשל `https://host:8443/`).
- **קישור סימבולי:** אם קובץ המסד הוא symlink, העדכון מחליף את הקישור בקובץ רגיל; קובץ היעד המקורי אינו משתנה.

## בדיקת מסד לפני הפצה

```bash

```

מדפיס דוח יכולות: טבלאות שנמצאו / חסרות / שמתעלמים מהן, זוגות לא שלמים, VIEW שמתחזה
לטבלה, ה-slug שנגזר, מצב WAL, מספר שורות `external_link` מול המגבלה, והפרות
`filePath`. ב-`external_default_commentator` הוא מזהיר על שורות בלי ספר מפרש, עם

עם `--library=<seforim.db>` הוא מזהיר גם כש-`library_folder` הוא שם של קטגוריה עליונה
בספרייה הרשמית (בלי הבדל של גרשיים): התיקייה אינה מתמזגת לקטגוריה, ובעץ יופיעו שתיים.
יוצא בקוד שאינו 0 כשיש בעיה חוסמת.

## עדכונים למסד (למפרסמים)

מסד יכול להצהיר על מקור עדכונים. אוצריא מעדכנת אותו רק באישור המשתמש, ורק כשהמניפסט חתום במפתח שנעוץ אצלה.

### השדות ב-`schema_meta`

| מפתח | ערך |
|---|---|
| `library_id` | חובה לעדכונים. זהה בכל הגרסאות. |
| `db_version` | מספר שלם, עולה בכל גרסה. |
| `update_manifest_url` | כתובת `https://` של `manifest.json`. |
| `update_public_key` | המפתח הציבורי (ed25519, base64) מ-`keygen`. |

מסד שחסר בו אחד מהם — או שערכו פגום — אינו מתעדכן לעולם. `validate_personal_db` מדווח על כך.

המפתח והכתובת **נעוצים** בפעם הראשונה שאוצריא רואה את המסד. גרסה שמצהירה על מפתח אחר, כתובת אחרת או `library_id` אחר נדחית. אין החלפת מפתח: מפתח שאבד או הוחלף מחייב כל משתמש להסיר את המסד ולצרף אותו מחדש. שמרו את המפתח הפרטי בגיבוי ובסוד.

### תהליך הפרסום

```bash
# פעם אחת:
dart run tool/personal_db_update.dart keygen --out my-lib.key
# מכניסים למסד את update_public_key ואת update_manifest_url שהפקודה מדפיסה.

# בכל גרסה: מעלים את db_version במסד, ואז
dart run tool/personal_db_update.dart pack my-lib.db --out release \
    --url-prefix https://github.com/<owner>/<repo>/releases/download/v5
dart run tool/personal_db_update.dart sign release/manifest.json --key my-lib.key
dart run tool/personal_db_update.dart verify release/manifest.json --db my-lib.db --parts release
```

`pack` דוחס ב-zstd (נדרשת תוכנת `zstd` בנתיב, או `--zstd <path>`; `--compression none` בלי דחיסה) ומחשב sha256 לכל חלק ולמסד כולו.

מעלים את קובצי החלקים לכתובות שבמניפסט, ואת `manifest.json` ו-`manifest.json.sig` לכתובת שב-`update_manifest_url` (החתימה בדיוק באותה כתובת עם `.sig`). אחרי החתימה אסור לשנות אף בית במניפסט — גם לא רווח.

### מסד גדול מ-2GB, ואחסון בכל שרת

- `--part-size <bytes>` מפצל את הקובץ הדחוס לחלקים (`.001`, `.002`...). ברירת המחדל, 1900MiB, מתחת למגבלת הקובץ של GitHub Releases. החלקים משורשרים לפי הסדר ואז נפרסים.
- כל שרת `https` מתאים: GitHub Releases, אחסון קבצים או שרת פרטי. `--url-prefix` הוא התיקייה שבה החלקים יישבו. המניפסט והחלקים יכולים לשבת בשרתים שונים.
- אוצריא מסרבת ל-`http`, לכתובת IP, ל-`localhost` ולשמות ברשת מקומית, גם אחרי הפניה (redirect).

### מבנה המניפסט

```json
{
  "format": 1,
  "library_id": "my-lib",
  "db_version": 5,
  "release_notes": "Plain text, shown as-is.",
  "full": {
    "compression": "zstd",
    "size": 3221225472,
    "sha256": "<sha256 of the final .db>",
    "parts": [
      {"url": "https://host/v5/my-lib-5.db.zst.001", "size": 1992294400, "sha256": "<sha256>"},
      {"url": "https://host/v5/my-lib-5.db.zst.002", "size": 704643072, "sha256": "<sha256>"}
    ]
  }
}
```

`db_version` חייב להיות גדול מזה של המסד המותקן — אין חזרה לגרסה ישנה. שדות לא מוכרים מתעלמים מהם. המניפסט עד 1MB, והמסד עד 64GB.

השדה האופציונלי `delta` מחזיק תיקונים בין גרסאות: `[{"from_db_version", "from_sha256", "compression": "zstd-patch", "size", "sha256", "parts"}]`. `size` ו-`sha256` הם של קובץ ה-`.db` שמתקבל — בדיוק כמו ב-`full`. `from_sha256` משמש לבחירה כשיש כמה תיקונים אפשריים לאותה גרסה: הלקוח מחשב SHA-256 של הבסיס פעם אחת ב-isolate ובוחר את התיקון הקטן ביותר שמתאים. כשיש תיקון אפשרי יחיד לפי `from_db_version`, סוג הדחיסה, גודל ההורדה והמכונה, הוא נבחר בלי קריאת הבסיס. בכל מקרה הלקוח מאמת את הפלט מול ה-`sha256` החתום, ובכשל או אי-התאמה מוריד את `full`. ערך דלתא שלקוח אינו מבין מדולג, והוא מוריד את `full`; `full` עצמו נבדק בקפדנות ואינו יכול להיות `zstd-patch`.

### תיקוני דלתא (הורדה קטנה בהרבה)

```bash
dart run tool/personal_db_update.dart pack my-lib.db --out release     --url-prefix https://host/v5 --delta-from my-lib-v4.db --delta-from my-lib-v3.db
dart run tool/personal_db_update.dart sign release/manifest.json --key my-lib.key
dart run tool/personal_db_update.dart verify release/manifest.json --db my-lib.db     --parts release --delta-from my-lib-v4.db --delta-from my-lib-v3.db
```

- `--delta-from <old.db>` חוזר על עצמו עד 4 פעמים, ומקבל מסדים קודמים של אותו `library_id` עם `db_version` נמוך מהחדש (אחרת שגיאה). לכל אחד נוצר תיקון `zstd --patch-from`, מפוצל לחלקים כמו הקובץ המלא.
- תיקון שאינו קטן מהקובץ המלא נזרק עם אזהרה — אין טעם להוריד אותו.
- **מגבלת 2GiB:** אוצריא מחילה תיקון רק כשהקובץ המותקן קטן מ-2GiB (תקרת חלון ה-zstd) ורק על מכונת 64 סיביות. מעבר לכך מפרסמים את הקובץ המלא בלבד; התיקון עדיין יכול להיות במניפסט, הלקוח פשוט יתעלם ממנו.
- `verify --parts` מחיל כל תיקון על ה-`--delta-from` שה-sha256 שלו תואם, באותו קוד שהתוכנה מריצה, ובודק גודל ו-sha256. זה דורש `libzstd` (`--zstd-lib <path>` או `LIBZSTD_PATH` כשאינו בנתיב). בפענוח מומלץ `--memory=2048MB` בבדיקה ידנית עם `zstd` משורת הפקודה.
- **הלקוח בוחר לבד:** התיקון הקטן ביותר שישים (אותה גרסה מותקנת, אותו sha256, הורדה קטנה מהקובץ המלא) נבחר; כל כשל — מיפוי, פענוח, גודל או sha256 — חוזר בשקט להורדת הקובץ המלא, בלי הודעת שגיאה. הקובץ הסופי נבדק תמיד מול ה-sha256 שבמניפסט החתום.

### עדכון מסד מצורף (למשתמש)

- **מקור עדכונים:** בכרטיס "מסדים מצורפים" כל מסד מציג "אין מקור עדכונים", "חתום · <דומיין>", או "מקור העדכון השתנה — לא יעודכן" (המסד מצהיר עכשיו על כתובת או מפתח אחרים מאלה שנעוצו בצירוף; כדי לקבל את המקור החדש יש להסיר ולצרף מחדש). כשמצרפים קובץ שיש לו מקור, חלון הסיכום מציג את הדומיין ושהעדכונים חתומים.
- **מתי נבדק:** יחד עם בדיקת עדכוני הספרייה — רק כש"עדכוני תוכנה וספרים" ועדכון אוטומטי פעילים, לא במצב לא מקוון, ובאותה תדירות שנבחרה לבדיקת העדכונים. "בדוק עדכונים" בשורת המסד בודק מיד.
- **התקנה:** שום עדכון לא מותקן לבד. "עדכון זמין (גרסה X)" ← "עדכן" פותח חלון עם הדומיין, הגרסה, גודל ההורדה ומה חדש, וההורדה מתחילה רק באישור. ההתקדמות מוצגת בכרטיס ואפשר לבטל בזמן ההורדה.
- **מה קורה לקובץ:** גם מסד מקושר מתעדכן במקומו (באותה תיקייה). הקובץ הישן נשמר כ-`<שם>.db.bak-update` עד שהחדש נפתח ונבדק (אותו מסד, אותו מפתח, הגרסה שהוצעה); אחרת הישן חוזר. אם התוכנה נסגרה באמצע, הגיבוי מוחזר בהפעלה הבאה. דרוש מקום פנוי לקובץ החדש ליד המסד (ולהורדה הדחוסה בתיקיית הנתונים); תיקייה לקריאה בלבד או כונן מנותק מדווחים כשגיאה והקובץ הישן לא נוגע.

## מסדים רשמיים

אוצריא מפרסמת גם מסדים אישיים רשמיים (כרגע: "מחברי זמננו"). כל עוד מסד רשמי לא מותקן, הכרטיס "מסדי ספרים אישיים" בהגדרות מציע להוריד אותו, עם שמו וגודל ההורדה. "לא תודה" או הסרת המסד מצמצמים את ההצעה לשורה "מסדים רשמיים", וממנה אפשר להציג אותה שוב. ההצעה לא מופיעה בשום מקום אחר.

- **מה הופך מסד לרשמי:** מניפסט שנחתם במפתח שקבוע בקוד התוכנה, וקובץ שתואם ל-sha256 שבו. זה קורה בהורדה דרך התוכנה, בייבוא חבילה לא-מקוונת, או בזיהוי של קובץ שצורף ידנית (בהמשך). עותק כזה מסומן בתגית "רשמי".
- **מה לא הופך מסד לרשמי:** `library_id`, `update_public_key` או `update_manifest_url` שכתובים בקובץ. קובץ ששונה, או שאין לגרסה שלו מהדורה מפורסמת, נשאר מסד אישי רגיל: בלי תגית ובלי עדכון אוטומטי.
- **קובץ שצורף ידנית:** כולל קובץ שהורד לפני שהתוכנה תמכה במסדים רשמיים. אחרי עליית התוכנה, ברקע ובמצב מקוון, התוכנה מורידה את המניפסט החתום של הגרסה שהקובץ מצהיר עליה (`releases/download/v<db_version>/manifest.json`). אם הקובץ זהה לגרסה שפורסמה, הוא מסומן "רשמי" ומתעדכן מכאן לבד. ניסיון שלא הצליח חוזר רק כשהקובץ משתנה, או אחרי שבוע. בלי רשת הוא חוזר בעלייה הבאה.
- **קובץ מקושר שזוהה כרשמי:** התוכנה לא כותבת לקובץ שלכם. העדכון הראשון מותקן כעותק בתיקיית התוכנה, והקובץ המקורי נשאר ברשימה כ"מזהה כפול" (אפשר להסיר אותו).
- **שני עותקים:** רק אחד פעיל, והשני מסומן "מזהה כפול". עותק מאומת קודם לעותק שאינו מאומת. אם שניהם מאומתים או שניהם אינם מאומתים, העותק שבתיקיית התוכנה קודם.
- **ייבוא בלי אינטרנט:** "ייבוא מקובץ" בהצעת ההורדה, או "עדכון מקובץ" בתפריט של מסד רשמי מותקן, מקבלים את `zmanenu-offline.tar.zst`: את הקובץ השלם, או, כשהוא מפוצל, את `zmanenu-offline.tar.zst.part-000` או את `zmanenu-offline.tar.zst.manifest.json` (כל החלקים צריכים להיות באותה תיקייה). באנדרואיד בוחרים את הקובץ השלם, או בוחרים יחד את כל החלקים ואת המניפסט אם קיים. התוכנה בודקת את החתימה ואת ה-sha256 בלי רשת, ומתקינה את המסד כעותק רשמי. חבילה עם גרסה ישנה מהמותקנת נדחית. מסייע ההורדה יכול להניח את החבילה (שלמה או בחלקים) בתיקייה `מסדים אישיים/להתקנה` שבתיקיית הנתונים, והתוכנה תתקין אותה בעלייה הבאה ותמחק אותה. חבילה פגומה נשארת שם, ומוצגת הודעה.
- **בהגדרת ספרייה חדשה:** "הורד גם את מחברי זמננו" (כבוי כברירת מחדל) מוריד את המסד אחרי שהספרייה הותקנה. בייבוא הספרייה מתיקייה, חבילת `zmanenu-offline.tar.zst` (שלמה או בחלקים) שנמצאת באותה תיקייה מותקנת גם היא.
- **עדכון אוטומטי:** מסד רשמי מתעדכן לבד, בלי חלון אישור, באותם תנאים של עדכון הספרייה: "עדכוני תוכנה וספרים" ו"סינכרון הספרייה באופן אוטומטי" פעילים, לא במצב לא מקוון, ובתדירות שנבחרה. ההורדה משתמשת בדלתא כשאפשר, באותו גיבוי ושחזור של כל עדכון.
- **עותק ששונה:** לפני עדכון התוכנה בודקת שהקובץ המותקן הוא בדיוק הגרסה שהותקנה (גרסה ו-sha256). אם לא, העדכון לא מותקן, מוצגת הודעה, ובשורת המסד מופיע "הורדה מלאה" שמחליף את הקובץ בגרסה הרשמית העדכנית.
- **שחזור מגיבוי:** סימון "רשמי" לא משוחזר מארכיון גיבוי. אחרי שחזור, אפשר להוריד את המסד הרשמי מחדש מההגדרות.
