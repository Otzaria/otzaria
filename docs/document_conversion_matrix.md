# מטריצת המרת מסמכים — מה נתמך בכל פורמט

מסמך זה הוא **חוזה ההמרה** של אוצריא: לכל אלמנט במסמך המקור, איזה HTML
הממיר מייצר, ובאילו פורמטים.

עודכן: 2026-09-13. כל שורה אומתה מול הקוד ומול הרצת המרה על מסמך בדיקה
אמיתי בכל אחד מהפורמטים.

## מקרא הפורמטים

| עמודה | פורמטים |
|---|---|
| **OOXML** | ‎.docx‎, ‎.docm‎, ‎.dotx‎, ‎.dotm‎, וכן ‎.xml‎ בדיאלקט Flat OPC |
| **XML03** | ‎.xml‎ בדיאלקט WordprocessingML 2003 (`w:wordDocument`) |
| **ODT** | ‎.odt‎ |
| **RTF** | ‎.rtf‎ |
| **DOC** | ‎.doc‎, ‎.dot‎, ו-‎.wbk‎ שתוכנו Word בינארי |
| **HTML** | ‎.html‎, ‎.htm‎ |

‎.wbk‎ מנותב לפי תוכנו: חבילת OOXML → עמודת OOXML, בינארי → עמודת DOC.

מקרא: ✅ נתמך · ⚠️ נתמך חלקית (ראו הערה) · ❌ אינו נתמך · — אין לו ייצוג
בפורמט.

כל שורה בספר ב-`<div>` מיותר. שאר הפורמטים אינם מצהירים על כיווניות ברמת
הפסקה כלל, ולכן העמודה שלהם `—`.

על פני כמה שורות.
⁸ **חייב להישאר בשורה אחת.** פירוקו לשורות היה מציג את התוכן המוסתר כטקסט
רגיל ומאבד את ההתקפלות — שינוי משמעות, לא רק אובדן עיצוב. `open` נשמר.

### כלל היישור

יישור שמאל/ימין נכתב רק כשהוא **חד-משמעי**:

| מצב | התנהגות |
|---|---|
| `center` | תמיד נכתב |
| ערך פיזי (`left`/`right`) ב-OOXML/XML03/ODT | נכתב — הפורמטים האלה כותבים יישור רק כשהוא מפורש |
| ערך פיזי ב-RTF, פסקה LTR | `\qr` נכתב; `\ql` מדולג — Word כותב אותו כמעט בכל פסקה, ולכן הוא ברירת מחדל ולא הצהרה |
| ערך לוגי (`start`/`end`, `\ql`/`\qr`) בפסקה LTR | נפתר ונכתב |
| ערך לוגי בפסקה **RTL** | **מדולג** |

**למה:** מפיקי המסמכים חלוקים בפירוש היישור הלוגי בפסקה RTL. אותו מסמך
נשמר ב-Word כ-`w:jc="end"` בלי `w:bidi` (כלומר ימין), ב-LibreOffice כ-
`fo:text-align="end"` עם `rl-tb` (שלפי תקן ODF הוא שמאל), וב-RTF כ-`\ql`
בתוך `\rtlpar`. Word עצמו כותב יישור מפורש כמעט בכל פסקה, ולכן הכרעה
שגויה אינה משפיעה על פסקה בודדת אלא **מיישרת ספר עברי שלם לצד ההפוך**.
בהיעדר סימון, הקורא מיישר לפי כיוון הטקסט — וזו התוצאה הנכונה כמעט תמיד.

כך מבנה השורות נשמר, ואיתו אינדקסי תוכן העניינים וההערות האישיות.
⁸ **ב-‎.doc‎ בינארי מחולצות רק תמונות inline** (תו-מציין 0x01 עם
`sprmCPicLocation`). תמונה **צפה** (מעוגנת) יושבת ב-`PlcSpaMom` וב-
`OfficeArtContent` שבזרם הטבלה, ואינה נקראת. במסמך הבדיקה חולצו 2 מתוך 14.
⁹ המסגרת מצוירת רק כשהמסמך מצהיר עליה — `draw:stroke` שאינו `none` ב-ODT,

כולן הייתה מציירת מאות תיבות מדומות.
¹⁰ **טקסט הקישור נשמר במלואו** — רק העטיפה ב-`<a>` אינה נוצרת.
¹¹ רק סכימות `http`, `https`, `mailto` ועוגן פנימי (`safeLinkTarget`, מקור
יחיד ב-`otzaria_markup.dart`). סכימה אחרת מוצגת כטקסט — לרבות `javascript:`,
`data:`, `file:` ו-`otzaria://`, שבהן הקורא מפעיל פעולות באפליקציה. **חריג
ב-HTML:** קישורים שפותחים ספר (`book://`, `otzaria://open/book|pdf/…`) נשמרים.
¹² ב-HTML מוטמעות שתי צורות: `data:` base64 של PNG/JPEG/GIF/BMP/WebP, וקובץ
תמונה **בתוך תיקיית הספר** (יציאה ב-`../` נחסמת). כתובת רשת, `file:` ו-
protocol-relative מדולגות — אין גישת רשת בהמרה ואין בקורא. `image/svg+xml`
נדחה: הוא XML שיכול לשאת `<script>`, ומנוע התצוגה אינו מרנדר אותו בלאו הכי.
¹³ `background-image` דורש הבאת משאב לתוך `style`; הממיר אינו כותב URL
כלשהו ל-`style`.
¹⁴ **רק כשהמסמך כתב אותה במנגנון של אוצריא** — הצירוף
`<sup class="footnote-marker">` ואחריו מיד `<i class="footnote">`, כפי
שמתועד ב"עריכת ספר באוצריא". הממיר מזהה אותו ופולט אותו מחדש דרך
`otzaria_markup.dart`, כך שגוף ההערה מוסר מגוף הספר ומוצג כמפרש בחלונית
הצד. **אין** היריסטיקת noteref כמו ב-EPUB: הערה שנכתבה כקישור פנימי רגיל
(`href="#fn1"`) נשארת קישור, והקורא מנווט לשורתה לפי ה-`id` (ראו ¹⁵).
¹⁵ נשמר **רק** ל-`id`/`name` שקישור פנימי במסמך מפנה אליו; שאר המזהים
מדולגים, כדי ששורות הספר לא יתמלאו בעוגנים שאיש אינו משתמש בהם.
`HtmlLinkHandler` מאתר את שורת היעד לפי `id="…"`, ולכן הכותרת נושאת את
המזהה על התגית עצמה (שורה שאינה פותחת ב-`<h#` אינה נקלטת ב-`TocParser`).

## CSS — תכונות שעוברות מהמסמך (HTML בלבד)

שכבת התצוגה מקבלת את ה-HTML של הספר כמות שהוא ומגישה אותו ל-`HtmlWidget`,
ולכן תכונה שמנוע התצוגה מכיר אמורה לשרוד את ההמרה. שאר הפורמטים אינם
מייצרים `style` מתוך המסמך אלא בונים אותו בעצמם, ולכן הטבלה הזו שייכת
ל-HTML בלבד.

מקור האמת הוא `lib/utils/text/css_whitelist.dart`, ו-`css_whitelist_test.dart`
מקבע את שני הכיוונים — מה עובר ומה נדחה.

| תכונה | ערכים שמתקבלים | הערה |
|---|---|---|
| `color`, `background-color` | שם, `#RGB`/`#RRGGBB`/`#RRGGBBAA`, `rgb()`, `rgba()`, `hsl()`, `hsla()` | שחור וגם רקע לבן מנוקים — הם שוברים את המצב הכהה |
| `font-weight` | `bold`, `normal`, 100–900 בכפולות של 100 | `bold`/`700` הופכים ל-`<b>`; שאר הדרגות נשמרות כהצהרה |
| `font-style` | `italic`, `normal` | `italic` הופך ל-`<i>` |
| `font-size` | `%`, `em`, `px`, `pt`, `xx-small`…`xx-large`, `larger`/`smaller` | |
| `font-family` | רשימה מופרדת בפסיקים; שם מרובה-מילים נכתב מחדש במרכאות בודדות | |
| `line-height` | מספר, `%`, `em`, `px`, `normal` | |
| `text-align` | `left`/`right`/`center`/`justify`/`start`/`end` | **בלוק בלבד** — על `<span>` הקורא מתעלם |
| `vertical-align` | `super`, `sub`, `top`, `bottom`, `middle`, `baseline` | |
| `white-space` | `nowrap`, `normal`, `pre`, `pre-wrap`, `pre-line` | |
| `direction` | `ltr` בלבד | RTL הוא ברירת המחדל של הקורא |
| `display` | `inline-block`, `inline`, `block` | `none` מדלג על האלמנט כולו |
| `text-decoration`(`-line`/`-style`/`-color`) | קווים, סוג וצבע | ממופה לתגיות `<u>`/`<s>` כשאפשר |
| `text-decoration-thickness` | **אחוזים בלבד** | הקורא מתעלם מפיקסלים |
| `text-shadow` | 2–4 רכיבים לכל צל, כמה צללים בפסיקים | צל עם 5 רכיבים מבטל את כל התכונה בקורא |
| `list-style-type` | כולל `hebrew` ו-`lower-greek` | |
| `border`(`-top`/`-right`/`-bottom`/`-left`/`-style`/`-width`/`-color`) | עובי, סוג וצבע | |
| `padding`, `margin` (וכל הצדדים) | 1–4 מידות | |
| `width`, `height` | מידה | |

**מה שנדחה, ומדוע:** `rem` (הקורא מתעלם), `oblique`, `bolder`/`lighter`,
עובי קו בפיקסלים, צל עם חמישה רכיבים ומעלה — כולם הצהרות מתות שהקורא לא
היה מצייר, וכתיבתן רק מנפחת כל שורה בספר. `transform`, `position`, `float`,
`opacity`, `border-radius`, `animation` ו-`text-emphasis` אינם ברשימת ההיתר
כלל, ולכן נעלמים מאליהם.

**מאפיינים מדור קודם** שהקורא מכיר ומתקבלים גם הם: `<font color>`,
`align`, `dir`, `bgcolor`, `valign`, `border`, `cellpadding`, `colspan`,
`rowspan`, `start`, `reversed`, `type`, `value`, `open`, `width`, `height`,
`alt`, `title`.

## נספח: מה נבדק בפועל

מסמך בדיקה יחיד, שנשמר ב-11 קבצים בכל הפורמטים, הומר בשרשרת המלאה
(‎`convertDocumentFileSync`‎) ונמדד מול כל שורה בטבלאות שלמעלה.

ששת קובצי משפחת OOXML (‎.docx‎/‎.docm‎/‎.dotx‎/‎.dotm‎ ושני קובצי Flat OPC)
מייצרים פלט **זהה** — 1,150 שורות ו-347,142 תווים עבריים בכל אחד. זהו
קריטריון השקילות בין הפורמטים.

מדדים שכל 11 הקבצים מסכימים עליהם: **631 הערות שוליים**, שלוש טבלאות,
ואפס יישורי-שמאל מזויפים. תיבות הטקסט: 8 בכל פורמט שמצהיר עליהן.

שלושה פערים שנמצאו הם של **מסמך המקור** ולא של הממיר, ומתועדים כאן כדי
שלא ייחקרו שוב:

1. כל סוגי הרשימות במסמך הבדיקה מצביעים על אותה הגדרה אחת (`numId=1`),
   ולכן כולם מוצגים כמספור עשרוני רץ. הממירים תומכים בכל הפורמטים —
   הבדיקות ביחידה מקבעות זאת לכל פורמט בנפרד.
2. פסקת ה"יישור לשמאל" איבדה את היישור שלה בשמירה, ואין בקובץ שום פסקה
   מיושרת-שמאל.
3. גרסת ה-‎.docx‎ מפצלת פסקאות שגרסת ה-ODT ו-WordML 2003 שומרות שלמות
   (1,150 שורות מול 763). אין הבדל בתוכן — מספר התווים העבריים זהה.

עמודת ה-HTML לא נמדדה מול אותו מסמך — אין לו גרסת ‎.html‎ שנשמרה מ-Word.
היא מקובעת ב-`test/utils/file/html_to_otzaria_test.dart` (שורה לכל תא
בטבלאות שלמעלה) וב-`advanced.html` שבקורפוס ה-fixtures, שעובר את השרשרת
המלאה ב-`test/tool/document_fixtures_generator_test.dart` — שם נבדק גם
שכל וקטור בחוזה האבטחה **אינו** מגיע לפלט.
